# 동작 규격 (SPEC)

**이 문서가 답하는 질문**: *무엇이 어떻게 동작해야 하는가.*
왜 그렇게 정했는지는 `DECISIONS.md`, 지금 어디까지 됐는지는 `STATUS.md` 에 있다.

**마지막 갱신**: 2026-08-28

---

## 화면 흐름

```
[시작 화면]  자주 하는 루틴이 큰 버튼으로 하나씩 · 항목 수 · 버전 날짜
     │                                   └─ ☰ ─→ [가끔 하는 루틴] ─┐
     │  루틴 버튼을 누르면 바로 시작                                │
     ▼ ←──────────────────────────────────────────────────────────┘
[항목 화면]  ← 여기가 본체. 한 번에 한 항목만.
     │  완료 (또는 시간 지정 항목의 자동 종료)
     │     └→ 띵 + 짧은 진동 + 사라지는 전환 → 다음 항목
     ▼
[요약 화면]  전체 소요시간 + 항목별 소요시간 목록
     │  닫기 / 처음으로
     ▼
  기록은 남기지 않고 버린다
```

**시작 방식**: 앱은 **사용자가 열 때만** 시작한다. 정해진 시각의 예약 알림은 없고,
앞으로도 넣지 않는다 (D-009). 이건 브라우저의 한계를 감수한 게 아니라 그렇게 정한 것이다.

## 시작 화면 — 빈도로 두 층 (D-023)

**자주 하는 루틴**(`tier: 'main'`)은 여기 **큰 버튼으로 하나씩** 뜬다.
버튼에는 루틴 이름과 항목 수가 들어가고, **누르면 바로 시작**한다 — 고르기와 시작이
한 번의 조작이다.

**가끔 하는 루틴**(`tier: 'more'`)은 오른쪽 위 **`☰`** 를 눌러야 나오는 별도 화면에
같은 모양의 버튼으로 늘어선다. 닫기는 `✕` 또는 `Esc`.

- 열린 시각으로 **하나를 제안**해 둔다. 경계는 **정오(12:00)** — 00:00~11:59 는 모닝,
  12:00~23:59 는 이브닝. 제안된 하나만 **채워서** 그리고, 부제에 `지금 시간` 을 붙인다.
  어디까지나 제안이고 다른 버튼을 누르면 그만이다
- **제안은 화면을 그릴 때마다 다시 계산한다** — 앱을 종일 띄워 둔 기기에서 정오를
  넘겼는데 옛 제안이 남아 있으면 안 된다
- 루틴이 늘어 목록이 화면보다 길어지면 스크롤된다. `☰` 안쪽은 제안하지 않는다
- 오른쪽 아래 구석에 버전 날짜를 작게 표시 (`CLAUDE.md` 8번)
- 소리 토글과 편집 화면 진입점은 화면 아래

**제1 원칙과 충돌하지 않는다** — 여기 늘어놓는 것은 *루틴 이름*이지 *항목*이 아니다.

## 항목 화면 — 제1 원칙이 걸린 곳

**보이는 것**

| 요소 | 크기 | 내용 |
|---|---|---|
| 항목 이름 | 아주 크게 | 이 화면의 주인공 |
| 보조 설명 | 작게 | 있을 때만 (예: "코로 4초, 입으로 8초") |
| 타이머 | 작게 | `이 항목 2:31 · 전체 14:02` |
| 진행 | 작게 | `3 / 9` 또는 얇은 진행바 |
| **완료 버튼** | 화면 아래쪽, 엄지가 닿는 곳에 크게 | |
| 건너뛰기 / 이전 | 완료 버튼보다 **눈에 띄게 작게** | 오작동 방지 |

**보이면 안 되는 것**: 다음 항목이 무엇인지, 남은 항목의 이름들.
"3 / 9" 처럼 **개수**는 괜찮다 — 내용이 보이는 게 문제다.

## 타이머 — 늘어나는 방식

- **카운트다운이 아니라 스톱워치.** 항목이 뜨는 순간 자동으로 0부터 올라간다
- **`setInterval` 로 누적하지 않는다.** 시작 시각(`Date.now()`)을 찍어두고 매 틱마다
  현재 시각과의 차이를 계산한다. 그래야 화면을 끄거나 다른 앱에 갔다 와도 시간이
  밀리지 않는다 (D-004)
- 항목에 시간이 지정되어 있으면(예: 명상 10분) 그 시간에 도달할 때 **띵 + 진동**이
  울린다. 다만 **자동으로 넘어가지는 않는다** — 넘기는 것은 항상 사용자의 완료 조작이다
- 건너뛴 항목은 요약에서 `건너뜀` 으로 표시하고 시간은 세지 않는다

## 완료 피드백

세 가지가 함께 나간다. **소리는 보조**이고, 화면 피드백이 주 신호다 (D-003).

1. **소리**: WebAudio 로 합성한 짧은 "띵" (오디오 파일 없음).
   첫 사용자 조작 시점에 AudioContext 를 깨워 둔다 (브라우저 자동재생 정책)
2. **진동**: 지원하는 기기에서만 짧게. 미지원이면 조용히 건너뛴다
3. **화면**: 항목이 사라지는 전환 + 진행 표시 갱신

소리 끄기 토글을 둔다 (상태는 localStorage).

## 요약 화면

- 전체 소요시간, 항목별 소요시간 목록, 건너뛴 항목 표시
- **닫으면 사라진다.** 날짜별 기록·연속일수·통계 없음 (D-005)

## 루틴 항목 관리

**기본 목록은 파일 안에** `ROUTINES` 상수로 들어 있다 (D-006).
**루틴 하나가 키 하나**이고, 여기 적은 순서가 곧 화면에 뜨는 순서다 (D-023).

```js
const ROUTINES = {
  morning: {
    label: 'Morning Routine',   // 화면에 크게 뜨는 이름
    short: '모닝',               // 좁은 자리 (진행 중 표시 · 편집 탭)
    tier:  'main',              // 'main' → 시작 화면 / 'more' → ☰ 안
    theme: 'auto',              // 화면 톤. 'auto' 는 기기 설정을 따른다 (D-027)
    items: [
      { name: '물 한 잔', note: '',                   minutes: null },
      { name: '호흡',     note: '코로 4초, 입으로 8초', minutes: 3    },
    ],
  },
  evening: { /* … theme: 'dark' … */ },
};
```

**루틴을 늘릴 때 손댈 곳은 이 객체뿐이다.** 시작 화면·`☰` 목록·편집 탭·회귀 검사가
전부 `ROUTINES` 를 읽어 스스로 늘어난다.

- `minutes: null` → 완료 버튼으로만 넘어간다
- `minutes: 3` → 3분에 도달하면 알림이 울린다 (넘어가지는 않는다)

**편집 화면에서 되는 것**: 항목 추가·삭제·이름/설명/시간 수정·순서 변경,
**기본값으로 되돌리기**, **내보내기 / 불러오기**.

**내보내기·불러오기가 왜 필요한가** — localStorage 는 출처(origin)마다 따로 논다.
`file://` 로 편집한 루틴은 나중에 URL 방식으로 옮기면 따라오지 않고, 기기 간에도
공유되지 않는다. 편집한 목록을 JSON 텍스트로 복사해 다른 곳에 붙여넣는 것이 서버
없이 옮기는 유일한 방법이다 (D-007).

## 진행 상태의 저장

**저장하지 않는다.** 진행 중에 파일을 닫거나 새로고침하면 처음부터다.
기록을 남기지 않기로 한 이상(D-005) 중간 상태만 남기는 것은 앞뒤가 맞지 않고,
"어제 하다 만 것"이 오늘 되살아나는 편이 더 헷갈린다.

localStorage 에 저장되는 것은 **편집한 루틴 목록**과 **소리 끄기 설정** 둘뿐이다.

## 화면·입력

- 처음부터 반응형 한 파일. 맥/태블릿/폰 모두 같은 파일 (D-001)
- 세로 좁은 화면을 기준으로 잡고 넓은 화면에서는 가운데 정렬로 폭을 제한
- 완료 버튼은 최소 44px 이상, 엄지 닿는 아래쪽
- 루틴 진행 중에는 **화면 꺼짐 방지** (Wake Lock API, 미지원이면 조용히 무시)
- 화면 톤은 루틴의 `theme` 이 정한다. **넷 다 `'auto'` 라 기기의 밝게/어둡게
  설정을 그대로 따른다** (D-027). `'light'`·`'dark'` 로 못박을 수는 있지만 지금
  쓰는 곳은 없다
  - 이브닝을 어둡게 못박던 것은 뺐다. 근거("잠들기 전 밝은 화면을 피한다")는
    그대로지만 기기의 야간 모드가 그 일을 하므로, 앱이 따로 판단하면 어긋난다.
    ⚠ **기기를 종일 밝게 두면 이브닝도 밝게 뜬다** — 그게 문제면 값 하나로 되돌린다
- 키보드 (맥에서 쓸 때)
  - 시작 화면 · `☰` 화면: **숫자키 `1`·`2`·`3`…** 위에서부터 n 번째 루틴을 시작.
    `Enter`/`Space` 는 제안된 루틴, `Esc` 는 `☰` 닫기
  - 항목 화면: `Space`/`Enter` = 완료 · `→` = 건너뛰기 · `←` = 이전

## 아직 정하지 않은 것

- **`수련과 운동` · `출국 전 체크리스트` 의 실제 항목** — 지금 들어 있는 것은
  자리표시자다. 실제 목록을 받으면 `items` 를 통째로 교체한다 (B-27 · B-28)
- **가끔 하는 루틴을 더 만들지** — 필요해지면 `tier: 'more'` 로 한 칸 더한다 (B-30)
