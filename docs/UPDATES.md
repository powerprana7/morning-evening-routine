# 갱신 이력 (UPDATES)

**이 문서가 답하는 질문**: *언제 무엇이 바뀌었나.*

버전은 날짜다(`index.html` 의 `VERSION`, `CLAUDE.md` 8번). 여기 **한 버전에 한 칸**씩,
**새것이 위로** 쌓는다. 이미 적은 칸은 고치지 않는다 — 틀렸으면 다음 칸에서 바로잡는다.

**다른 문서와의 경계**

| | |
|---|---|
| `STATUS.md` | **지금** 뭐가 되나 — 늘 현재 시점 하나만 있다 |
| `UPDATES.md` | **언제** 뭐가 바뀌었나 — 지난 것을 지우지 않고 쌓는다 (이 문서) |
| `DECISIONS.md` | **왜** 그렇게 정했나 — 근거와 버린 대안 |
| `BACKLOG.md` | **다음에** 뭘 하나 |

한 줄로 줄이면: 여기는 **바뀐 것**, 결정 장부는 **바꾼 이유**다.
그래서 이 문서의 각 칸은 결정 장부와 할 일 번호(`D-0xx` · `B-xx`)를 가리키기만 하고,
근거를 여기에 옮겨 적지 않는다.

**한 칸에 적는 것**: 바뀐 것 · 안 바뀐 것 · 확인한 것과 못 한 것.
마지막 항목이 특히 중요하다 — 이 프로젝트에서 "된다"는 **손으로 눌러 본 것**만이다
(`CLAUDE.md` 1번).

## 2026-08-28 (7) — 화면 톤이 기기 설정을 따른다

**한 줄**: 맥의 시스템 설정, 안드로이드의 다크 테마를 그대로 따라간다. (B-34, D-027)

### 바뀐 것

**1. `theme` 에 `'auto'` 가 생겼고, 루틴 넷 다 그것이다**

| 루틴 | 전 | 후 |
|---|---|---|
| Morning Routine | `light` | **`auto`** |
| Evening Routine | `dark` | **`auto`** |
| 수련과 운동 | `light` | **`auto`** |
| 출국 전 체크리스트 | `light` | **`auto`** |

`'light'` · `'dark'` 는 못박는 값으로 남아 있지만 **지금 쓰는 곳은 없다.**

**2. ⚠ 이브닝의 강제 어둡게가 빠졌다** — 이게 이 갱신에서 실제로 달라지는 부분이다.
기기를 종일 '밝게'로 두면 **이브닝 루틴도 밝게 뜬다.** 잠들기 전 밝은 화면을
앱이 막아 주던 것이 사라진다. 맥 야간 모드·안드로이드 다크 테마가 해질녘에
저절로 어두워지니 앱이 따로 판단할 필요가 없다고 본 것인데, **그 판단이 틀렸다면
`ROUTINES.evening.theme` 을 `'dark'` 로 되돌리면 된다 — 값 하나다.**

**3. 홈 화면 앱의 위쪽 띠 색도 따라간다** — 이건 CSS 가 못 정하고
`meta[theme-color]` 로 정해져서, JS 가 지금 톤을 계산해 넣는다.
**루틴 도중 기기 설정이 바뀌어도**(해질녘 자동 전환) 그때 다시 맞춘다.

**4. 어두운 색을 두 벌 적는다** — CSS 가 선택자와 미디어 질의를 한 규칙으로
못 묶는다. 한 벌로 끝나는 `light-dark()` 도 있지만 옛 안드로이드 웹뷰에서
통째로 무시될 수 있어 버렸다 (D-002 · 어디서 열어도 동작해야 한다).

**5. 회귀 검사** — 187건 → **197건**. 8번을 새로 뒀다.
**두 벌의 색이 글자 그대로 같은지**, CSS 와 JS 가 **같은 질의**를 보는지,
루틴 넷이 다 `auto` 인지를 본다. 일부러 한 글자를 어긋나게 해서
검사가 실제로 실패하는 것까지 확인했다.

- 색 자체는 그대로다. 밝은 톤 · 어두운 톤의 값을 하나도 바꾸지 않았다
- 뷰 방식(`view`)·루틴 자리(`tier`)·항목 내용
- ⚠ `수련과 운동` 7개는 여전히 자리표시자다 (B-27)

### 확인한 것

로컬 서버 + 크롬. **이 맥이 지금 '어둡게'라서 그쪽이 진짜 기기 설정이다.**

| 확인한 것 | 결과 |
|---|---|
| 회귀 검사 | ✅ 197건 통과 / 실패 0 |
| 기기가 어둡게 → 시작 화면·모닝·이브닝 전부 어둡게 | ✅ |
| `light` 로 못박으면 밝게 뜨는가 | ✅ (못박는 값이 아직 살아 있다) |

  본 것이지 진짜 밝게 설정에서 본 것이 아니다. 맥 시스템 설정을 밝게로 바꿔
  한 번 열어 봐 주면 판정된다

## 2026-08-28 (6) — push 를 묻지 않는다

**한 줄**: 일하는 방식이 바뀌었다. 앱은 그대로다. (B-33, D-026)

커밋했으면 **push 까지 한다.** `CLAUDE.md` 7번의 "원격 업로드는 반드시 먼저 묻는다"를
뒤집었다 — 이 앱은 여러 기기에서 같은 것을 보는 것이 전제라 **올라가지 않은 커밋은
되돌아갈 지점이 아니라 끝나지 않은 작업**이기 때문이다.

대신 **관문이 한 칸 앞으로 옮겨갔다.** 이 저장소는 Public 을 벗어날 수 없고
push 는 되돌릴 수 없는 공개다. 그래서 **공개되면 안 되는 것을 애초에 커밋하지
않는다** 가 지켜야 할 규칙이 됐다. 비밀번호·토큰·개인정보가 섞일 낌새가 있으면
커밋 전에 멈추고 묻는다.

**되돌리기·이력 삭제(`reset --hard` · `push --force` · 브랜치 삭제)는 그대로
먼저 묻는다.** push 여부와 다른 종류의 위험이다.

`index.html` 은 손대지 않았다. `VERSION` 도 그대로다.

## 2026-08-28 (3) — 목록 뷰는 체크리스트가 됐다

**한 줄**: 목록 뷰에서 **순서와 무관하게 아무 줄이나** 완료할 수 있다.
끝낸 것은 아래로 내려가 흐려진다. (B-32, D-025)

### 바뀐 것

**1. 줄마다 `완료` 단추** — 이것을 누르는 것이 곧 완료다. 위에서부터 차례로
할 필요가 없다. 5번을 먼저 챙겼으면 5번을 누르면 된다.

**2. 끝낸 것은 아래로 내려간다** — 끝낸 순서대로 쌓이고 흐리게 뜬다.
그 앞에 `완료 4` 라고 적힌 구분선이 하나 들어간다. 위쪽에 남는 것이
**아직 안 한 것뿐**이라, 남은 개수를 세지 않아도 눈에 들어온다.

**3. 잘못 눌렀으면 `✓` 를 다시 누른다** — 끝낸 줄의 오른쪽 `✓` 가 취소 단추다.
`↩ 되돌리기` 는 마지막 하나만 되살리므로, 열네 줄을 훑다 엉뚱한 것을 눌렀을 때
쓸 것이 필요했다.

**4. 아래 단추의 뜻이 바뀌었다** (목록 뷰에서만)

| | 한 항목 뷰 | 목록 뷰 |
|---|---|---|
| 큰 단추 | `완료` (검은 큰 단추) | **`마치기`** — 작고 흐리게 |
| 왼쪽 | `← 이전` | `↩ 되돌리기` |
| 오른쪽 | `건너뛰기 →` | **없다** |
| 위쪽 숫자 | `7 / 27` | `3 / 14 · 5:12` |

`마치기` 를 **크고 검은 단추로 두지 않았다.** 진짜 조작이 줄마다 있는데 아래에
큰 단추가 있으면 그걸 눌러야 할 것처럼 보이고, 잘못 누르면 루틴이 끝나 버린다.
같은 이유로 목록 뷰에서는 `Enter`·`Space` 를 받지 않는다.

**5. 다 채우면 저절로 끝난다.** 채우지 못하고 `마치기` 를 누르면 남은 것이
요약에 **`안 함`** 으로 흐리게 남는다.

**6. 흐린 쪽이 뒤집혔다** — 전에는 아직 안 한 것이 흐렸는데(지금 항목을 돋보이게
하려고), 이제 끝낸 것이 흐리다. 목록 뷰의 주인공은 남은 일이다.
지금 항목을 검게 칠하던 강조도 없앴다 — 순서와 무관한 목록에서 하나를 강조하면
"이것부터 하라"가 되어 앞뒤가 안 맞는다.

**7. 안쪽 구조** — 기록이 스택에서 **끝낸 순서 목록**이 됐다.
`{ i, name, ms, skipped }` 로 항목 번호를 들고 다닌다. 예전에는 자리 번호가 곧
항목 번호였는데(순서대로만 끝냈으니까) 이제는 다르기 때문이다.
덕분에 **뷰를 오가도 진행이 이어진다** — 목록에서 5번만 체크하고 한 항목 뷰로
넘어가면 아직 안 한 1번이 뜬다.

**8. 회귀 검사** — 149건 → **160건**. 7번을 새로 뒀다. 줄 순서를 정하는
`listOrder()` 를 상태 없는 순수 함수로 빼서 검사가 직접 돌려본다.
**여기가 틀리면 훑는 도중 줄이 엉뚱한 데로 튀어 어디까지 했는지를 잃는다.**

### 안 바뀐 것

- **한 항목 뷰는 그대로다.** 완료·건너뛰기·이전·타이머·`@분` 알림 전부 예전 동작이다.
  모닝 루틴을 도는 경험은 하나도 안 바뀌었다
- **줄을 아무 데나 눌러도 완료되지는 않는다** — 단추라는 좁은 과녁을 일부러 남겼다.
  훑어보다 손이 스치는 것만으로 넘어가면 안 된다 (D-024 에서 정한 것)
- 기록·시간 재기·소리는 여전히 두 뷰가 **한 벌**을 쓴다
- ⚠ `수련과 운동` 7개와 `출국 전 체크리스트` 14개는 여전히 자리표시자다 (B-27·B-28)

### 확인한 것

로컬 서버(`python3 -m http.server 8742`) + 크롬.

| 확인한 것 | 결과 |
|---|---|
| 회귀 검사 | ✅ 160건 통과 / 실패 0 |
| 5 → 2 → 9 번을 순서 무시하고 체크 | ✅ 아래로 내려가 흐려지고, **누른 순서대로** 쌓인다 |

| `↩ 되돌리기` | ✅ 마지막에 끝낸 것 하나가 되살아난다 |

| 전부 체크 | ✅ `마치기` 없이 저절로 요약 14줄 |

### 확인 못 한 것 — 사람이 눌러야 한다

- **`완료` 단추가 엄지로 눌리는 크기인가.** 40px 로 잡았고 줄 간격도 그에 맞춰

- **한 손으로 열네 줄을 훑을 때 오른쪽 단추까지 손이 닿는가**
- 소리 · Wake Lock · 오프라인 · 맥앱 폴백 — 전부터 남아 있던 미검증

## 2026-08-28 (2) — 루틴마다 보는 방식이 다르다

> 같은 날 두 번째 갱신이다. 버전은 날짜라 `VERSION` 은 그대로 `2026-08-28` 이다.
> "한 버전에 한 칸"과 어긋나지만, **이미 적은 칸은 고치지 않는다**는 쪽을 택했다.
> 하루에 두 번 바꾸면 이렇게 `(2)` 를 붙인다.

**한 줄**: 뷰 방식이 사용자 설정이 아니라 **루틴의 성질**이 됐다. 순서가 중요한
루틴은 한 항목씩, 순서와 무관한 체크리스트는 전체 목록으로 열린다. (B-31, D-024)

### 바뀐 것

**1. 루틴 메타에 `view` 가 붙었다** — `theme` 옆이다.

```js
departure: {
  label: '출국 전 체크리스트', short: '출국 전',
  tier:  'more',
  theme: 'light',
  view:  'list',            // ← 이번에 늘어난 것
  items: [ /* … */ ],
}
```

| 키 | 루틴 | 뷰 |
|---|---|---|
| `morning` | Morning Routine | `one` — 한 번에 한 항목 |
| `evening` | Evening Routine | `one` |
| `practice` | 수련과 운동 | `one` |
| `departure` | 출국 전 체크리스트 | **`list` — 열네 개가 한 화면에** |

**2. 목록 뷰가 생겼다** — 항목 화면에서 카드 대신 전체가 뜬다.

- 지금 할 것은 **채운 줄**로 뜨고 **늘 화면 가운데로 끌어온다**
- 지나온 것은 걸린 시간(또는 `건너뜀`), 아직인 것은 흐리게 + 목표 시간(`10분`)
- **줄을 눌러도 완료되지 않는다.** 완료는 큰 `완료` 버튼 하나뿐이다 — 훑어보다
  손이 스치는 것만으로 항목이 넘어가면 안 된다

**3. 실행 중 전환 버튼** — 항목 화면 오른쪽 위, 루틴 이름 옆.
`▤ 목록` / `▣ 하나씩` 으로 **누르면 무엇이 되는지**를 적는다. 맥에서는 `v` 키.

**4. 전환은 그 회차에만 걸린다 — 저장하지 않는다.**
`start()` 마다 루틴의 `view` 로 돌아간다. 처음엔 `localStorage` 에 저장했다가
**되돌렸다** — 체크리스트에서 목록으로 본 것이 다음 날 아침 모닝 루틴까지
따라오면 이 앱이 존재하는 이유가 조용히 무너진다 (D-024).

**5. 회귀 검사** — 127건 → **149건**. 메타 검사(5번)에 `view` 를 넣고 6번을 새로 뒀다.
6번이 못박는 것은 **순서가 중요한 셋이 `'one'` 이라는 것**과 **뷰가 저장되지 않는다는
것**이다. 이 기능의 실패 모습이 "목록이 순서가 중요한 루틴까지 번지는 것"이라서다.

**6. 곁가지** — 목록 안 자동 스크롤에서 `scrollIntoView` 와
`scrollTo({behavior:'smooth'})` 가 둘 다 통하지 않아(바깥이 `overflow:hidden`)
`scrollTop` 을 직접 계산한다. `VERSION` 과 `sw.js` 캐시 이름(`routine-v3`)은
그대로다 — 날짜가 같고, 서비스워커가 네트워크 우선이라 갱신이 막히지 않는다.

### 안 바뀐 것

- **제1 원칙** — 뒤집지 않았다. **어떤 루틴에 걸리는 원칙이었는지가 밝혀진 것**이다
  (D-024). 순서가 중요한 루틴에서는 여전히 다음 항목이 보이지 않는다
- **진행 로직** — 완료·건너뛰기·이전·시간 재기·소리·Wake Lock 을 두 뷰가 똑같이 쓴다.
  `render` · `tick` · `advance` · `back` 의 동작은 그대로다
- 모닝·이브닝의 항목 내용과 순서, 텍스트 형식(`이름 | 설명 @분`), 시작 화면·`☰`·
  편집 화면·요약 화면의 생김새
- ⚠ **`수련과 운동` 7개와 `출국 전 체크리스트` 14개는 여전히 자리표시자다** (B-27·B-28)

### 확인한 것

로컬 서버(`python3 -m http.server 8742`) + 크롬으로 눌러 확인했다.

| 확인한 것 | 결과 |
|---|---|
| 회귀 검사 | ✅ 149건 통과 / 실패 0 |
| 출국 전 체크리스트가 **목록으로 열림** (14줄) | ✅ |
| 모닝·이브닝은 한 항목으로 열림 | ✅ |
| 회차 전환이 다음 루틴에 안 따라옴 (출국 전↔모닝 왕복) | ✅ |
| 아무것도 저장되지 않음 (`localStorage` 가 비어 있다) | ✅ |
| 목록에서 완료·이전·건너뛰기 — 지나온 줄의 시간·`건너뜀` 표시 | ✅ |
| 지금 항목 자동 스크롤 (짧은 화면 380px 에서도 늘 보인다) | ✅ |
| 어두운 톤(이브닝)에서 지금 줄이 읽히는가 | ✅ |
| 끝까지 완주 → 요약 28줄 · `처음으로` | ✅ |

### 확인 못 한 것 — 사람이 눌러야 한다

- **실제 폰에서 목록을 훑는 느낌** — 줄 높이·글자 크기가 엄지로 훑기에 맞는지,
  `▤ 목록` 버튼이 오른쪽 위에서 눌리는지. **이 기능의 값어치가 걸린 지점인데
  판정을 못 했다**
- **`▤` · `▣` 글자가 안드로이드에서 제대로 뜨는가** — 맥 크롬에서만 봤다.
  안 뜨면 두부(□)로 보인다
- **소리** — 로직을 건드리지 않았으나 실기기 확인은 별개다
- **Wake Lock · 오프라인 실행 · 맥앱 오프라인 폴백** — 전부터 남아 있던 미검증 (B-22)
- **`file://` 에서 직접 열었을 때** — 로컬 서버로만 봤다

## 2026-08-28 — 루틴을 2개에서 4개로, 빈도별로 나눠 배치

**한 줄**: 루틴이 더 이상 모닝·이브닝 둘이 아니다. 자주 쓰는 것은 시작 화면에,
가끔 쓰는 것은 `☰` 뒤에 둔다. (B-27 · B-28 · B-29, D-023)

### 바뀐 것

**1. 루틴 자료구조에 메타가 붙었다** — 루틴 하나가 키 하나다.

```js
practice: {
  label: '수련과 운동',      // 화면에 크게 뜨는 이름
  short: '수련·운동',        // 좁은 자리 (진행 중 표시 · 편집 탭)
  tier:  'main',            // 'main' → 시작 화면 큰 버튼 / 'more' → ☰ 안
  theme: 'light',           // 이 루틴을 도는 동안의 화면 톤
  items: [ /* … */ ],
}
```

루틴을 하나 더 늘릴 때 **손댈 곳은 이 객체뿐**이다. 시작 화면·`☰` 목록·편집 탭·
회귀 검사가 전부 `ROUTINES` 를 읽어 스스로 늘어난다.

**2. 루틴 두 개가 늘었다**

| 키 | 이름 | 자리 | 톤 | 항목 |
|---|---|---|---|---|
| `morning` | Morning Routine | 시작 화면 | 밝게 | 27 |
| `evening` | Evening Routine | 시작 화면 | 어둡게 | 28 |
| `practice` | 수련과 운동 | 시작 화면 | 밝게 | **7 · ⚠자리표시자** |
| `departure` | 출국 전 체크리스트 | `☰` 안 | 밝게 | **14 · ⚠자리표시자** |

⚠ **새 루틴 두 개의 항목은 자리표시자다.** 실제 목록을 받으면 `items` 를 통째로
교체한다 (B-27 · B-28). 코드에도 같은 표시를 주석으로 달아 두었다.

**3. 시작 화면이 바뀌었다**

- 모닝/이브닝 **토글 + `시작` 버튼**이 없어졌다. 대신 **루틴마다 큰 버튼 하나**가
  뜨고, 누르면 바로 시작한다 — 고르기와 시작이 한 번의 조작이 됐다
- 시간대 제안(정오 경계)은 남았다. 다만 이제는 "선택해 둔 상태"가 아니라
  **제안된 하나만 채워서** 그린다. 예전 `시작` 버튼이 있던 자리를 그것이 대신한다
- 제안은 **화면을 그릴 때마다** 다시 계산한다. 정오를 넘겨 돌아왔는데 옛 제안이
  남아 있는 일이 없다
- 오른쪽 위에 **`☰`** — 가끔 하는 루틴이 여기 있다. 닫기는 `✕` 또는 `Esc`

**4. 화면 톤이 루틴에 붙었다** — `body[data-mode="evening"]` → `body[data-theme="dark"]`.
어두운 톤은 이제 "이브닝이라서"가 아니라 **그 루틴의 `theme` 이 `dark` 라서** 걸린다.

**5. 편집 화면이 루틴 개수를 따라간다** — 탭이 `ROUTINES` 에서 만들어지고(4개),
상태줄이 `출국 전 14개 · 전체 4개 루틴 76개` 처럼 전체를 함께 보여준다.
클로드코드 지시문도 `ROUTINES.<키> 의 items 를` 로 바뀌어 어느 루틴이든 가리킨다.

**6. 키보드 (맥)** — 시작 화면과 `☰` 화면에서 **숫자키 `1`·`2`·`3`…** 이 위에서부터
n 번째 루틴을 시작한다. `Enter`/`Space` 는 제안된 것, `Esc` 는 `☰` 닫기.

**7. 회귀 검사** — 79건 → **127건**. 두 가지가 늘었다.
- 왕복·중복 검사가 `["morning","evening"]` 고정에서 `Object.keys(ROUTINES)` 로 —
  **루틴을 늘리면 검사도 저절로 늘어난다**
- 새 검사 5번 · 루틴 메타(`label`·`short`·`tier`·`theme`·`items`)가 갖춰졌는지.
  메타를 빠뜨리면 시작 화면에 안 뜨거나 톤이 어긋나는데, 화면을 안 띄우고 잡을 수
  있는 것이 여기까지다

**8. 곁가지** — `sw.js` 캐시 이름 `routine-v2` → `v3`,
매니페스트 설명에서 "모닝·이브닝" 을 뺐다(더 이상 둘이 아니다), `VERSION` → `2026-08-28`.

### 안 바뀐 것

일부러 그대로 둔 것들이다.
